## 二、问题清单

### P0 · 阻断发布

**P0-1 打不出 APK：Gradle 仓库模式冲突**（已修复，配置阶段已验证通过）
- 现象：`assembleDebug` 在配置阶段失败，`A problem occurred configuring project ':gradle'` → `Build was configured to prefer settings repositories over project repositories but repository 'maven' was added by settings file`
- 根因：全局注入脚本 `~/.gradle/init.d/mirror.init.gradle` 用 `beforeProject { project.repositories { maven {} } }` 给每个 project 加仓库；Flutter 3.47 的 `flutter_tools/gradle/settings.gradle.kts` 设了 `FAIL_ON_PROJECT_REPOS`，两者直接冲突。
- 修复：init 脚本改为 `beforeSettings` 往 `pluginManagement` / `dependencyResolutionManagement` 注入；项目内 `android/build.gradle.kts` 移除 `allprojects.repositories`，仓库统一在 `android/settings.gradle.kts` 的 `dependencyResolutionManagement` 声明（阿里云镜像保留）。

**P0-2 中文路径被 AGP 9 拒绝**（已修复，配置阶段已验证通过）
- 现象：`Your project path contains non-ASCII characters`，构建中断。
- 根因：路径 `E:\happy-english-app\快乐英语\kuaile_yingyu` 含中文，AGP 9 由警告升级为硬失败。
- 修复：`android/gradle.properties` 增加 `android.overridePathCheck=true`。
- 备选（更彻底）：把工程移到纯 ASCII 路径（如 `E:\projects\happy_english_app`）。当前选择保留中文目录，代价是升级 AGP 时要复查该开关。

### P1 · 功能/内容缺陷

**P1-1 单元测试已失效（9 条挂 2 条）**
- `scoreText("It's a cat.", "it is a cat")` 期望 100，实际 66.67。实现自 V1.3.5 起**不再展开缩写**（`it's` 保持单词，等价性交给 `sameGroup`），严格编辑距离下 3 vs 4 词必然扣分；正确断言应用 `coverageScore`（有吞词逻辑，返回 100）。
- `starsForDisplay(75)` 期望 3 星，实际 2 星。显示星级阈值早改为 85/65，测试仍按旧阈值。
- 结论：**是测试过期，不是运行时 bug**，但会造成 CI 永久红，必须先修测试再上流水线。

**P1-2 book12 内容与资源脱节**
- `content.json` 的 book12 只有 3 个单元 48 条，但 `assets/audio/book12` 里有第 4 单元共 96 个文件。
- 影响：六年级下册少一整个单元；多余文件白占包体。

**P1-3 慢速示范只覆盖一二年级**
- book1–4 共 620 条句子有 `_slow.mp3`；book5–12 的 270 条句子没有。
- 影响：高年级点“慢速”按钮**静默无效**（`_assetExists` 探测失败回落正常速，但 UI 仍显示“慢速”已选中），孩子以为切了没生效。

**P1-4 备份目录混进 assets**
- `assets/audio/_backup_v114_vol/` 196 个文件。
- 目前 pubspec 未声明该子目录，不打进 APK；但目录污染会让后续“整目录声明”时误打包。

**P1-5 156 个未引用音频随包发布**
- book2（44）、book3（60）、book4（52）的旧文件仍被 `assets/audio/bookN/` 目录声明收进 APK，约 6MB 无效体积。

### P2 · 体验/健壮性

**P2-1 播放失败无兜底**
`AudioService.play()` 没有 try-catch，`await _player.play(...)` 抛异常时上层 `onTap` 不处理 → 孩子点了没声音、无提示、无重试，只在控制台留一行错误。资源零缺失时不易触发，但只要有一次素材替换漏文件就复现。

**P2-2 图片无 `errorBuilder`**
3 处 `Image.asset` 缺兜底，缺图会直接报 RedScreen（release 下是灰块 + 异常）。

**P2-3 慢速是全局静态状态，跨页串味**
`AudioService._slow` 是静态变量，跟读页切“慢速”后，点读页、单词页播放也变慢且无任何提示。建议改为按页面/按播放调用传参，或至少在所有播放页显示状态。

**P2-4 无全局异常兜底**
`main()` 没有 `FlutterError.onError` / `runZonedGuarded` / `ErrorWidget.builder`。真机闪退后没有任何本地日志，“自己用着不崩”缺少事后定位手段。

**P2-5 慢速探测无缓存**
每次播放都 `rootBundle.load()` 整个 mp3 只为判断存在性，首次播放慢速会有明显延迟。应缓存 `Set<String>` 结果。

**P2-6 构建 JVM 参数对单模块过重**
`android/gradle.properties` 里 `-Xmx8G -XX:MaxMetaspaceSize:4G`，对单模块 debug 构建远超实际需要，内存紧张时会拖慢甚至卡在配置阶段。建议降到 `-Xmx3G -XX:MaxMetaspaceSize=1G`。

### 构建链最终定位（三层，逐层剥开）

用 `--offline` 让 Gradle 立即报缺件（而不是挂死等待），一层层剥出真因：

1. **插件 buildscript 绕过镜像**。每个 Flutter 插件在自己的 `android/build.gradle` 里写死 `google()/mavenCentral()`，独立于工程 settings 的仓库配置。国内直连 `repo.maven.apache.org` 拉 `kotlin-gradle-plugin`、AGP 8.x 等大件时连接建立但零吞吐，表现就是 Gradle 卡在配置阶段、CPU 长时间不动。
   处理：`tool/patch_pub_cache.py` 批量给 pub 缓存里的插件注入阿里云镜像（幂等，`flutter pub get` 后重跑）；`audioplayers_android` 与 `record_android` 的 Kotlin 版本对齐到缓存已有的 2.2.21。

2. **settings 仓库列表漏了 Flutter 官方仓库**。`io.flutter:flutter_embedding_debug` 只发布在 `storage.googleapis.com/download.flutter.io`，四个 Maven 源都找不到。
   处理：`android/settings.gradle.kts` 的 `dependencyResolutionManagement` 增加该仓库（用 `content { includeGroup("io.flutter") ... }` 限定范围）。

3. **NDK 工具链不认中文路径**（真因）。前两条解决后构建进入 native 编译，`jni` 插件报 `Expected output file ... libdartjni.so but there was none`。翻 CMake 日志发现它把 `快乐英语` 按 GBK 解释成乱码，`.so` 链接到了错误目录——`android.overridePathCheck=true` 只让 AGP 放行，CMake/Ninja 并不支持非 ASCII 路径。
   处理：建立英文联接 `E:\he_app -> 工程目录`，在该路径下构建。`tool/build_apk.ps1` 已把联接创建、镜像补丁、构建、产物提示固化成一键脚本。

**结果**：`app-debug.apk` 构建成功，446.8 MB（debug 含全部 ABI 且资源未压缩，属正常范围）。首次全量编译耗时约 27 分钟，之后有增量缓存。

**体积优化空间**（尚未做，需要时再推进）：`--release --split-per-abi` 可按设备裁 ABI；177 MB 的 PNG 主题图转 WebP 能再省一大截；`assets/models` 41 MB 若为离线语音模型，可改为按需下载。

**注意**：`~/.gradle/init.d/mirror.init.gradle` 属于用户全局环境，不在仓库版本控制内。换机器后需按 P0-1 重建；插件的镜像注入也要在新机器上跑一次 `tool/patch_pub_cache.py`。

## 六、release 出包打通与 CI 修复（第三轮）

debug 出包后按计划验证 release，CI 首跑也随之失败（`eb90595`，run `44287793812`：资源门禁、静态分析两项 success，构建 failure）。从本地复现 release 一路剥到根因，共四层：

1. **ABI 配置自相矛盾**。CI 用 `--split-per-abi`，而工程 `android/app/build.gradle.kts` 的 `ndk.abiFilters` 又显式锁了 `arm64-v8a`，AGP 直接拒绝：
   `Conflicting configuration : 'arm64-v8a' in ndk abiFilters cannot be present when splits abi filters are set`。
   处理：构建参数改为 `--target-platform android-arm64`，语义相同且不触发 splits。

2. **CMake 跑不起来（VC++ 运行库缺失）**。报错只有一句 `cmake.exe finished with non-zero exit value 268435466`，手动执行 `cmake --version` 才看到真因是 `0xC0000135`（STATUS_DLL_NOT_FOUND）——`D:\Android\Sdk\cmake\3.22.1\bin` 只有 exe，System32 里只有 `vcruntime140` 的 CLR 版本，缺标准运行库。
   **推论**：上一轮 debug 首次成功其实是侥幸，它复用了别的构建留下的 CMake 缓存，从未真正重新 configure。修法是安装 VC++ Redistributable（`vc_redist.x64`）。

3. **插件在 AGP 9 下漏设 namespace**。`audioplayers_android`、`google_mobile_ads`、`jni`、`jni_flutter` 共 5 个插件都写 `if (project.android.hasProperty('namespace'))` 才设置 namespace，这个判断在 AGP 9 下为假，于是报 `Namespace not specified`。
   处理：写进 `tool/patch_pub_cache.py`（新增 namespace 修补，并支持 Linux/macOS 的 pub 缓存路径），CI 在 `flutter pub get` 之后必须执行该脚本——否则 runner 上全新下载的插件没有补丁，必然失败。

4. **Engine 构件源被重置**。`io.flutter:arm64_v8a_release` 只发布在 `storage.googleapis.com/download.flutter.io`，国内连接被强制断开（`Connection reset`）。实测官方中国镜像 `storage.flutter-io.cn` 返回 200。
   处理：`android/settings.gradle.kts` 改为中国镜像优先、googleapis 兜底，并用 `content { includeGroup }` 限定到 `io.flutter` 及六个 ABI/构建类型的 group。

**结果**：`app-release.apk` 构建成功，**318.2 MB**（debug 446.8 MB）。补丁后增量复跑 18.9 秒通过，可稳定复现。代码提交 `041c1d0` 并推送，CI 重新触发。

**release 包签名现状**：沿用 debug key（`signingConfig = signingConfigs.getByName("debug")`），自用安装没问题；若以后要分发，需配正式 keystore 并移除该行。

**体积优化进展**：ABI 裁剪与 PNG→WebP 已落地（见第七节）；`assets/models` 41 MB 评估后决定保留（Vosk 离线识别在用，见第七节）。

## 七、体积优化：PNG → WebP

安装包 318 MB 的构成很集中：图片 169.1 MB、音频 61.0 MB、离线语音模型 39.3 MB、题库 0.7 MB，三项资源占了 85%，引擎和代码本身只有二三十兆。所以只处理图片一项。

**做法**：新增 `tool/to_webp.py`，把 `assets/images` 下 744 张 PNG 逐张转成同名 WebP（quality 82、method 6、保留原分辨率），再把题库 `content.json` 里 1477 处 `.png` 引用批量改成 `.webp`。原 PNG 不删，移到 `工具\_tmp\_png_backup_20261118`。

**结果**：

| 项 | 前 | 后 |
|---|---|---|
| 图片资源 | 169.1 MB（744 张 PNG） | **24.2 MB（744 张 WebP）** |
| release APK | 318.2 MB | **173.3 MB** |

压缩比 14%，省 145 MB。压缩效果最差的几张（`book10/U1_S5` 等）仍保留 40% 左右，说明高细节图也没崩。

**验证**：`tool/check_assets.py` → `problems_total 0`、`images 25.4 MB`；`dart analyze lib test` → 0 issue；`flutter test` → 9/9；本地 release 重建 69.7 秒通过。

**代价与风险**：WebP 是有损格式（quality 82），但同尺寸下肉眼与 PNG 无明显差异；Flutter 原生支持 WebP 解码，无需额外依赖。**唯一待确认项**：真机上图片显示是否正常，需要在验收清单里补一条"随便翻几页确认主题图清晰、无花屏"。

**`assets/models` 39.3 MB 为什么保留**：查过引用链，`lib/services/speech_service.dart:34` 明确加载 `assets/models/vosk-model-small-en-us-0.15.zip` 并交给 `vosk_flutter_service` 做跟读识别，`scoring.dart` 还依赖它的词表行为。删掉等于废掉跟读打分；改成"按需下载"虽然能省 39 MB，但孩子首次使用必须联网，与"离线能用"的目标冲突，不划算。

**音频 61 MB 不动**：已是 64 kbps 单声道，再降码率会明显影响音质，而音质是之前反复修正过的点。

**剩余可做**：音频若真要再压，只能考虑重采样或合并长句，收益有限；读下来最划算的一刀已经砍完了。

### CI 闭环（第三轮补充）

release 在本地跑通后，CI 仍连续失败 4 次，逐次剥出的问题都不是本地能提前看到的：

5. **runner 不保证有 CMake 3.22.1**。本地 SDK 里正好装了这个版本才跑通，CI 上只能显式 `sdkmanager "cmake;3.22.1"` 补装。
6. **Flutter 版本漂移（最关键的一条）**。CI 用 `channel: stable` 每次都拉最新版，而最新 Flutter 要求 AGP ≥ 9.1.1，工程是 9.1.0，构建直接报错拒绝：
   `Your project's Android Gradle Plugin version (9.1.0) is lower than Flutter's minimum supported version 9.1.1`。
   这里的取舍很清楚：门禁的价值是"CI 结论能代表本地"，所以把 CI 钉到 `flutter-version: '3.47.4'`（与本地一致），而不是为了迁就最新 Flutter 去升级 AGP——升级会引入新一轮插件兼容风险，且本地已验证 9.1.0 可用。
7. **失败日志不可读**。GitHub 的 job 日志需要认证才能下载，annotations 里只有 Node 版本之类的无关警告。处理：构建步骤 `tee` 到 `build.log`，失败时把 `What went wrong` 整段合并成一条 annotation 输出（逐行发会被折叠，反而丢掉关键行）。
